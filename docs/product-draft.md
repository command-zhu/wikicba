# LLM Wiki 产品与实现草案

状态：需求讨论稿。已确认的行为与建议实现分开记录；尚未实现。

## 已确认的产品行为

- Windows 本地桌面应用，管理真实文件；接收浏览器下载、已有文件和文件夹，后续扩展其他数据源。
- 项目区可绑定多个文件夹，并指定默认收纳目录；绑定不搬动已有文件。一个目录不能绑定多个项目。
- 外部拖入默认移动，可切换复制；明确的落点优先于自动规则。文件操作记录可查看，并在状态允许时撤销。
- 本地规则按扩展名、文件名关键词等进行初步分流；唯一命中直接执行，冲突时询问，无法匹配时进入杂物区。
- 全部项目共用重要／紧急四象限待办，可按项目筛选；支持直接新建、编辑、拖动、排序和完成。
- 将文件拖到待办象限空白处创建待办，以文件名作为可编辑标题；拖到已有待办上关联文件。
- 侧边悬浮窗口支持吸附、展开收起、始终置顶；收起显示小按钮与未完成数量。
- 关闭主窗口后驻留托盘；开机启动由用户开启。
- Skill 与桌面应用独立。Skill 由与桌面应用运行在同一台电脑上的独立 Agent 执行。暂不研究 dsh 和 qwenpaw 的具体适配。
- 后续 Skill 负责内容理解、深入归类、待办与知识提取、每日 Markdown 记录及 Wiki 链接。

## 建议的交互细节

项目卡片展示绑定目录与近期文件。拖入项目区时只在该项目内匹配；通用收集入口可跨项目匹配。拖入具体目录时尊重该选择。

规则优先级为：明确落点、项目规则、通用规则、杂物区。同优先级存在多个目标时让用户选择。规则编辑器支持条件、目标目录、优先级、启停和样例预览。目录名称用于建议规则，确认后保存明确映射。

例如会议关键词规则可优先于 PPT 扩展名规则，使“产品周会.pptx”进入会议目录。截图规则结合图片类型与文件名判断。拖放预览展示目的地、移动或复制模式及命中原因，批量操作显示各文件结果。

绑定文件夹与导入文件夹作为不同操作。父子目录跨项目重叠建议禁止，避免同一文件存在两个项目归属；Windows 路径大小写及目录链接需要规范化检查。

待办字段包括标题、说明、完成状态、重要性、紧急性、排序、可选截止时间、项目及文件链接。拖动象限改变重要性和紧急性；截止时间暂不自动改变象限。

悬浮窗窄模式显示精简待办与收集入口，展开后显示项目或四象限。关闭窗口与退出应用分别处理，退出后不承诺后台运行。

## 建议技术方案

Electron + React + TypeScript，SQLite 保存项目、目录绑定、规则、文件索引、待办和操作记录。原文件保存在真实目录中。

主进程提供受限文件操作、数据库、规则引擎、目录监听、托盘及窗口管理；渲染界面通过有限 IPC 接口访问能力，不直接执行文件系统操作。文件操作与规则引擎独立于界面，便于测试和 Agent 复用。

文件使用稳定 ID 关联待办和日志，路径作为可更新属性。监听外部变化，失联文件提示修复；不能保证任意外部移动都能自动追踪。

## 文件操作可靠性

- 同名文件不静默覆盖，支持保留两份或跳过。
- 跨盘移动先复制并校验完整性，成功后才删除源文件。源文件在操作期间变化时中止删除并报告。
- 使用持久操作状态记录处理中、成功、失败和待恢复状态；重启后核对未完成操作。
- 文件被占用、权限不足或磁盘空间不足时保留可恢复状态，报告逐文件结果。
- 撤销核对源与目标状态；后续文件修改或目标冲突时不盲目覆盖。
- 目录递归导入需处理目录链接及循环；默认不递归跟随链接。
- 待办空白处拖入的文件最终收纳位置、批量文件创建一个还是多个待办，仍待确定。

## 本机 Agent 协作建议

桌面应用执行确定性的规则分流；外部 Agent 运行 Skill 理解内容与生成笔记。应用日常工作不依赖 Agent 在线。

建议提供版本化接口，支持列出项目与目录用途、读取增量变更、按文件 ID 获取授权内容、请求归类移动、创建或更新待办、写入每日笔记，以及读取执行结果。所有写入复用应用的操作队列和日志。

Agent 与应用同机运行，可在权限允许时读取绑定目录中的文件。建议先提供本机命令行接口，让 Agent 查询项目、读取增量记录、请求移动文件和更新待办；具体通信机制在实现阶段确定。文件移动和待办写入统一经过应用服务，以维护日志、撤销与文件关联。暂不需要共享盘、远程内容传输或局域网服务。

Agent 写请求携带唯一请求 ID 与预期文件版本；重试不重复创建任务或移动文件，版本冲突返回明确结果。接口限制于已配置目录。应用离线时显示未执行，恢复后再处理。

规则已分流的文件仍应进入 Agent 的增量待处理队列，不能只依赖杂物区扫描。区分已收集、已初步分流、已由 Agent 处理等状态，避免漏掉知识提取。

每日记录引用实际来源，区分用户任务与模型建议；生成时间、休眠后的补执行及 Wiki 具体结构后续确定。

## 实施阶段与验收

1. 文件工作台：项目和多目录绑定、杂物区、拖拽移动／复制、规则预览与分流、日志与撤销。
2. 待办工作台：全局四象限与项目筛选、编辑和拖动、关联文件、悬浮窗、托盘和置顶。
3. Agent 接口：增量处理、授权文件访问、归类和待办写入、每日记录与 Wiki 接入。

在 Windows 实测：绑定两个目录后导入并核对默认移动和复制切换；验证会议与 PPT 规则优先级、冲突、未匹配回退；验证四象限拖动及文件关联；验证重启持久化、悬浮与托盘。文件操作覆盖跨盘、同名、占用、批量部分失败、撤销和中断恢复。接口阶段验证重试幂等、越界目录拒绝与离线恢复。
